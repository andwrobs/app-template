source, config, dependencies, and agent files. Filebonsai was reference only: nothing
there was changed or imported. This audited the template and workflow, not
Filebonsai's backend.

## Taken from Filebonsai

Kept: one root contract and reading map; the task skill's outcome, paths, acceptance,
focused checks, and honest handoff; short PR summaries; CLAUDE importing AGENTS with
one skills source; proportional evidence and rendered UI checks; observed status with
next steps; small decision records; and a plain backlog with IDs, acceptance, and
dependencies, ordered by status. Optional agent profiles (MAINT-03) and generated API
clients (API-01) are in the backlog.

Left out: product invariants and domain docs, automatic PR, push, and publish
authority, mandatory backend reviews, fixed branches, Java, Swift, and persistence
roles and pipelines, Docker and Auth setup, storage and wire contracts, branding and
design images, user settings, worktrees, scheduled-task locks, Filebonsai's own status
and product tasks, and treating a missing task ID as done.

## Recommendation

Make the folder reliable first: the reviewed Aria catalog with licenses, then Form,
Table, and Pacer examples that show real failure, pending, and keyboard behavior, then
a browser harness to protect refreshes. Prefer a versioned repository template or a
create-react-router custom template over owning an npm CLI, which only pays off for
renaming, example removal, filtering, and provenance. Publishing, the repository,
naming, and the license stay explicit choices.
